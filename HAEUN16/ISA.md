# HAEUN-16 Instruction Set Architecture (ISA)

HAEUN-16은 **16비트 고정 길이 명령어**를 사용하는 단순 RISC 스타일 CPU이다.  
모든 명령어는 1 word(16bit)이며, 상위 **4비트 opcode**로 연산을 구분한다.

---

## 1. 레지스터 파일

| 레지스터 | 인코딩 `[1:0]` | 너비 | 설명 |
|----------|----------------|------|------|
| R0       | `00`           | 16bit | 범용 레지스터 |
| R1       | `01`           | 16bit | 범용 레지스터 |
| R2       | `10`           | 16bit | 범용 레지스터 |
| R3       | `11`           | 16bit | 범용 레지스터 |

- PC(Program Counter)는 별도 모듈로 관리한다.
- 메모리는 `ram` 모듈(65536 word)과 연결한다.

---

## 2. 명령어 워드 공통 형식

```
 15 14 13 12 | 11 10 |  9  8 |  7 ... 0
+-------------+-------+-------+----------+
|   OPCODE    |  Rd   |  Rs   |  imm/0   |
+-------------+-------+-------+----------+
   4 bit        2 bit   2 bit    8 bit
```

| 필드 | 비트 | 설명 |
|------|------|------|
| OPCODE | `[15:12]` | 연산 코드 |
| Rd | `[11:10]` | 목적/대상 레지스터 |
| Rs | `[9:8]` | 원본 레지스터 (R-R 형식) |
| imm8 | `[7:0]` | 8비트 즉값 (부호 없음, 0~255) |

형식별로 미사용 비트는 `0`으로 두는 것을 권장한다.

---

## 3. Opcode 목록

| OPCODE `[15:12]` | 명령어 | 형식 | 설명 |
|------------------|--------|------|------|
| `0000` | NOP | — | 아무 연산 없음 |
| `0001` | LOAD | I-type | `Rd ← imm8` |
| `0010` | STORE | M-type | `RAM[imm8] ← Rs` |
| `0011` | ADD | R-type | `Rd ← Rd + Rs` (ALU ADD) |
| `0100` | SUB | R-type | `Rd ← Rd - Rs` (ALU SUB) |
| `0101` | AND | R-type | `Rd ← Rd & Rs` |
| `0110` | OR | R-type | `Rd ← Rd \| Rs` |
| `0111` | XOR | R-type | `Rd ← Rd ^ Rs` |
| `1000` | JMP | J-type | `PC ← imm8` (절대 주소, word 단위) |
| `1001` | JZ | J-type | `Rd == 0` 이면 `PC ← imm8`, 아니면 `PC+1` |
| `1010` | CALL | J-type | `RAM[sp] ← PC+1`, `sp--`, `PC ← imm8` |
| `1011` | RET | — | `sp++`, `PC ← RAM[sp]` |
| `1100` | OUT | I/O | `IO[port] ← Rs[7:0]` (port 0 = UART TX) |
| `1101` | IN | I/O | `Rd ← IO[port]` (상위 8비트 0) |

`1110` ~ `1111` : 예약

---

## 4. 명령어별 상세

### 4.1 NOP

```
15 12  11 0
+------+-----+
| 0000 |  0  |
+------+-----+
```

- 동작: 없음
- PC만 다음 명령으로 진행

---

### 4.2 LOAD (I-type)

```
15 12 | 11 10 |  7 ... 0
+------+-------+----------+
| 0001 |  Rd   |   imm8   |
+------+-------+----------+
```

- 동작: `Rd ← imm8` (상위 8비트는 0으로 확장)
- 예: `LOAD R0, 5` → R0 = 5

**인코딩 예**

| 어셈블리 | 16진수 | 2진수 (개념) |
|----------|--------|----------------|
| `LOAD R0, 5` | `0x1005` | `0001_00_00000101` |
| `LOAD R1, 3` | `0x1403` | `0001_01_00000011` |

---

### 4.3 STORE (M-type)

```
15 12 | 11 10 |  9  8 |  7 ... 0
+------+-------+-------+----------+
| 0010 |  0 0  |  Rs   |   imm8   |
+------+-------+-------+----------+
```

- 동작: `RAM[imm8] ← Rs` (주소 = imm8, word 주소)
- Rd 필드 `[11:10]`는 사용하지 않음 (`00`)

**인코딩 예**

| 어셈블리 | 16진수 |
|----------|--------|
| `STORE R2, 10` (R2 값을 주소 10에 저장) | `0x220A` (`0010_00_10_00001010`) |

---

### 4.4 R-type (ADD, SUB, AND, OR, XOR)

```
15 12 | 11 10 |  9  8 |  7 ... 0
+------+-------+-------+----------+
| opc  |  Rd   |  Rs   | 00000000 |
+------+-------+-------+----------+
```

| OPCODE | 명령어 | 동작 |
|--------|--------|------|
| `0011` | ADD | `Rd ← Rd + Rs` |
| `0100` | SUB | `Rd ← Rd - Rs` |
| `0101` | AND | `Rd ← Rd & Rs` |
| `0110` | OR | `Rd ← Rd \| Rs` |
| `0111` | XOR | `Rd ← Rd ^ Rs` |

- ALU 입력: A = Rd 현재값, B = Rs → 결과를 Rd에 기록
- `[7:0]`는 `0`

**인코딩 예**

| 어셈블리 | 16진수 |
|----------|--------|
| `ADD R0, R1` | `0x3100` (`0011_00_01_00000000`) |
| `SUB R2, R3` | `0x4B00` (`0100_10_11_00000000`) |

---

### 4.5 JMP (J-type)

```
15 12 |  11 ... 0
+------+-----------+
| 1000 |   imm8    |
+------+-----------+
```

- 동작: `PC ← imm8` (다음 Fetch 주소)
- Rd/Rs 필드 없음; 하위 12비트 중 `[7:0]`만 주소로 사용 (현재 설계는 8비트 주소 공간 = 256 word 프로그램 영역)
- 확장 시 `[11:0]` 12비트 주소로 확장 가능

**인코딩 예**

| 어셈블리 | 16진수 |
|----------|--------|
| `JMP 0` | `0x8000` |
| `JMP 16` | `0x8010` |

---

## 5. 실행 사이클 (CPU 동작 개요)

각 명령어는 다음 단계로 처리한다 (7단계 `cpu.v` 구현 예정).

1. **Fetch** — `PC`로 `RAM`에서 명령어 읽기  
2. **Decode** — opcode / Rd / Rs / imm8 해석  
3. **Execute** — ALU 연산 또는 주소 계산  
4. **Writeback** — 레지스터 또는 메모리 갱신, PC 갱신  

| 명령어 | PC 갱신 |
|--------|---------|
| NOP, LOAD, ADD, … | `PC + 1` |
| JMP | `PC ← imm8` |
| JZ | `Rd==0` 분기 |
| CALL / RET | RAM 스택 (`sp`, 초기 255) |
| OUT / IN | 포트 I/O (FPGA: port 0 → UART) |

### 4.6 JZ (v2)

```
15 12 | 11 10 |  7 ... 0
+------+-------+----------+
| 1001 |  Rd   |   imm8   |
+------+-------+----------+
```

- `Rd != 0` → `PC+1`
- `Rd == 0` → `PC ← imm8`

### 4.7 CALL / RET (v2)

**CALL**

```
15 12 |  7 ... 0
+------+----------+
| 1010 |   imm8   |
+------+----------+
```

- `RAM[sp] ← PC+1`, `sp ← sp-1`, `PC ← imm8`
- 스택: word 주소 255 downward

**RET**

```
15 12  11 0
+------+-----+
| 1011 |  0  |
+------+-----+
```

- `sp ← sp+1`, `PC ← RAM[sp]`

### 4.8 OUT / IN (v2)

**OUT** `OUT Rs, port` — `1100 | 00 | Rs | port8`  
**IN** `IN Rd, port` — `1101 | Rd | 00 | port8`

| port | 장치 |
|------|------|
| `0` | UART TX (115200 8N1, Tang Nano 9K pin 17) |

## 6. 예제 프로그램 (8단계 통합 테스트)

다음 프로그램은 `R0 = 8`이 되어야 한다.

```asm
    LOAD R0, 5      ; R0 = 5
    LOAD R1, 3      ; R1 = 3
    ADD  R0, R1     ; R0 = R0 + R1 = 8
```

| 주소 | 명령어 | 기계어 (hex) |
|------|--------|----------------|
| 0 | LOAD R0, 5 | `1005` |
| 1 | LOAD R1, 3 | `1403` |
| 2 | ADD R0, R1 | `3100` |

RAM 초기화 시 주소 0~2에 위 값을 순서대로 로드한다.

## 8. 설계 제약 및 확장

- **즉값 범위**: 8비트 (`0~255`). 큰 상수는 여러 LOAD/ADD로 구성.
- **STORE 주소**: 8비트 → 프로그램/데이터를 저주소 영역에 배치 (통합 테스트용).
- **스택 깊이**: 256 word RAM 상단 (`sp` 255→0). 중첩 CALL 주의.
- **예약 opcode**: `1110`~`1111` (VGA 등 향후).
- **메모리 맵**: 추후 ISA v2에서 RAM/IO 디코딩 추가 가능.
